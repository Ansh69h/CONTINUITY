# Support

## Getting help

- For usage questions and reproducible defects, open a [GitHub issue](https://github.com/Ansh69h/CONTINUITY/issues) with your Python version, CONTINUITY version, storage backend, a minimal example, and sanitized logs.
- For feature proposals, describe the use case, expected recovery semantics, compatibility needs, and alternatives considered.
- For suspected vulnerabilities, do not use a public issue. Follow [SECURITY.md](SECURITY.md).

## Before filing an issue

1. Check the README and the production/recovery guides.
2. Confirm the behavior on a pinned package version.
3. Remove credentials, user data, raw payloads, and idempotency keys from the report.
4. State whether the behavior was reproduced with SQLite, PostgreSQL, or Redis and whether the service was live or mocked.

CONTINUITY is an early-stage open-source project. Response times and support availability are not guaranteed. Security fixes, maintained integrations, and compatibility windows have not yet been formalized.
